🔍 The 5 Architectural Layers

  1. Layer 1: Mobile Client App — Expo Router UI, 8-tab routine logger, Brain Lab games, rPPG camera sensor, and multi-profile FamilyContext engine.
  2. Layer 2: Nginx Gateway — Single ingress point managing SSL, rate limiting, and routing (/, /ai/, /medication/).
  3. Layer 3: Microservices Core — 3 FastAPI services running BioGears C++ biophysics, Qwen2.5-14B LLM inference, and Medication Vault logic.
  4. Layer 4: Async Scheduler — Celery + Redis background worker executing DPSS (Deferred Physiology Synchronization System) midnight catch-ups.
  5. Layer 5: Data Persistence — PostgreSQL for relational clinical records, XML checkpoint files for exact biophysical state baselines.

🧬 BioGears Biophysics Simulation

Peer-reviewed C++ human physiology simulator solving organ-level circuits.

Input Translation

  • Nutrition $\rightarrow$ Carbs, Lipids, Amino Acids.
  • Activity $\rightarrow$ Work Output (Watts) & Heart Demand.
  • Medications $\rightarrow$ Pharmacokinetic Concentration.

Calculated Trajectories

  • Heart Rate (BPM) & Blood Pressure (MAP).
  • Blood Glucose & Plasma Insulin.
  • Respiration Rate & Oxygen Saturation (SpO₂).
Clinical Risk Analytics Built-In: Framingham 10-Year Cardiovascular Risk Score & ADAG HbA1c diabetic markers calculated directly from simulation data.

🔒 Privacy-First On-Device RAG AI

Why On-Device RAG?

Medical documents (lab reports, prescriptions) contain highly sensitive HIPAA/GDPR protected data. No raw medical files ever leave the user's phone.

  1. Step 1 (On Phone): User uploads medical PDF/Scan $\rightarrow$ Text extracted via local OCR.
  2. Step 2 (On Phone): Text is chunked & converted to vector embeddings locally.
  3. Step 3 (Query Time): Relevant context text is retrieved on-device.
  4. Step 4 (Local Server): Only anonymized text context is passed to local Qwen2.5-14B LLM.

🔄 Data Flow Sequence

1. Routine Input: User logs meal/workout on React Native Mobile Client.
2. Route Ingress: Request hits Nginx Proxy $\rightarrow$ Forwarded to BioGears Service (:8000).
3. XML Generation: BioGears Service loads patient state XML & builds scenario action file.
4. Biophysics Execution: C++ BioGears binary runs simulation & outputs trajectory CSV.
5. Live Dashboard Update: Updated vitals stream via SSE back to app gauges.
